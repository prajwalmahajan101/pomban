Working tracker for the **project-management reframing** release.
Five demo-able milestones (M1–M5) covering the 20 commits in the
source plan. ROADMAP.md owns the high-altitude phase view; this
file owns the milestone-by-milestone framing; the commit recipe

tests/` green. Tests land in the same commit as the feature.

## M2 — Hierarchy made first-class

**Goal.** Project → Sprint → Task chain becomes visible on every
screen.

**Scope.**

  the `AppScreen` base (`screens/base.py`,
  `widgets/context_header.py`); shows `Project · Sprint N/M ▮▮▯…
  · days left · (⇧P / ⇧F)`.
- Commit 6 — A5 — Sprint-aware Dashboard: tasks pane title cycles

  <name> (M/N · D days left)`, `Project board · <name>`, or
  `All tasks` based on `FilterState`.

  progress → switch filter → Kanban + Dashboard titles update →
  task-add without context fires picker.
- Pilot tests per screen asserting the dynamic strings.

**Dependencies.** M1 (`sprint_progress` helper).

## M2.5 — Engine / presenter decoupling

**Goal.** Establish a stable domain surface (`PombanEngine`) so the
TUI can evolve without breaking the engine, and the engine can be
unit-tested without a Textual pilot.

**Scope.**

- Commit 8.1 — New `src/pomban/core/engine.py` exposing
  `PombanEngine(db, settings, filters=None)`. It owns the
  long-lived domain objects (DB, `TimerEngine`,
  `SessionCoordinator`, `FilterState`, presets, hooks/plugins
  registry) and forwards their public surface as methods.
- Commit 8.2 — Replace the `add_task_from_input` /
  `submit_new_task` flow with engine commands that return
  typed outcomes: `engine.classify_new_task(text) -> Created
  | NeedsProject`. `PomodoroApp` interprets `NeedsProject` by
  pushing `ProjectPickerModal`; the engine never imports
  `textual`.
- Commit 8.3 — Migrate the remaining `PomodoroApp` state mutators
  (`set_active_project`, `set_active_sprint`, `start_focus_on`,
  `_on_phase_completed`, `action_toggle/reset/skip`,
  `delete_task_by_id`, etc.) to thin delegations to
  `self.engine.*`. `app.py` keeps only Textual concerns
  (bindings, screen routing, `push_screen`, `notify`,
  `switch_screen`).
- Commit 8.4 — New `tests/test_engine.py` driving `PombanEngine`
  directly (no pilot) for the command surface; existing pilot
  tests stay green by using the same accessors.

**Exit criteria.**

- `pytest -q` green; the test count grows by the new engine-level
  cases.
- `app.py` ≤ ~300 lines; no business logic, no DB writes outside
  `engine.*` calls.
- `grep -r "import textual" src/pomban/core/` returns nothing.
- `core/engine.py` exposes every state mutation the TUI needs as a
  named method; the M3 screens (built in the next milestone) wire
  to those methods rather than poking attributes on the app.

**Dependencies.** M2 (the `submit_new_task` flow being refactored
must already exist). Does not block M3 architecturally — M3
*depends on* this so each new M3 screen builds against the new
facade.

## M3 — Sprint lifecycle UX

**Goal.** User can run a sprint end-to-end without leaving the timer.

**Scope.**

- Commit 9 — B1 — `FirstRunModal` on empty-DB launch: prompt
  for a project name, create + activate it.
- Commit 10 — B2 — `SprintRunnerScreen` overlay bound to
  `Shift+R`: header (sprint/project/progress/days left), body
  (sprint tasks with status + per-task pomos), footer (`c` close +
  retro, `x` cancel, `e` edit retro, `Enter` start focus).
- Commit 11 — B3 — Completion modal: when `_on_phase_completed`
  observes `completed == pomodoro_target`, push non-blocking modal
  with *Close + Retro* / *Keep going* / *Later*, auto-dismiss 8 s.
- Commit 12 — B4 — `s` binding on Projects screen: creates +
  activates a sprint scoped to the focused project.

**Exit criteria.**

- Clean-DB walkthrough — first-run prompt → create sprint via
  `s` → `Shift+R` runner → focus session → completion modal at
  target → retro saved. Zero docs lookup.
- Pilot tests for the runner lifecycle and completion-trigger
  crossing.

**Dependencies.** M1 (`sprint_progress`), M2 (context header
already on every screen, so the runner inherits it), M2.5
(new screens build against `PombanEngine`).
